# Использование ИИ

- Использован ИИ: да, Claude (Sonnet 5), интерфейс приложения Claude Code (desktop).
- Затронутые файлы: README.md, `.github/workflows/ci.yml`, `.gitignore`,
  `evidence/pr01/graph.md`, `evidence/pr01/environment.json`,
  `evidence/pr01/report.json`, эта декларация.
- Помощь ИИ:
  - установка и починка окружения на Windows 10 (WSL2, переустановка сломанного
    дистрибутива Ubuntu, запуск Docker Desktop, включение WSL-интеграции,
    проверка проброса графики WSLg);
  - подготовка команд опыта и скриптов для сбора показаний в
    `evidence/pr01/` (без изменения самих ROS-команд из методички курса);
  - оформление README, `graph.md`, `report.json` и данной декларации по
    фактическим результатам запусков.
- Что сделано лично, без автоматизации: три реальных нажатия клавиши ↑ в
  интерактивном терминале `turtle_teleop_key` — исходное движение, попытка
  движения при пульте в чужом `ROS_DOMAIN_ID` (контрольная проверка отсутствия
  связи) и движение после восстановления домена; переключение
  `ROS_DOMAIN_ID` на пульте выполнялось вручную по указанным командам.
  `turtle_teleop_key` требует интерактивный терминал (падает без него:
  `Failed to get old console mode`) и поэтому не мог быть автоматизирован —
  это не решение, а техническое ограничение самой программы.
- Проверка: все файлы в `evidence/pr01/` — реальный stdout и коды завершения
  запущенных команд в контейнере с образом
  `osrf/ros:lyrical-desktop-full@sha256:e6b1cb53...9df3ebe`, ничего не
  сгенерировано вместо фактического запуска. Значения координат черепахи в
  `graph.md` взяты непосредственно из соответствующих файлов `pose-*.txt`.

## ПР02

- Затронутые файлы: `src/turtle_bringup/` (пакет и launch-файл),
  `.github/workflows/ci.yml` (добавлена сборка ПР02),
  `evidence/pr02/commands.md`, `evidence/pr02/types.md`,
  `evidence/pr02/report.json`.
- Помощь ИИ: генерация каркаса пакета через `ros2 pkg create`, правка
  `setup.py`/`package.xml` по инструкции методички, написание и запуск
  скриптов, воспроизводящих шаги руководства (сборка, `ros2 launch`, `ros2
  topic pub`, сравнение `ros2 topic info` для верного и неверного имени
  топика), оформление `commands.md`/`types.md` по фактическим выводам команд.
- Полностью автоматизировано без потери достоверности: в отличие от ПР01, в
  методичке ПР02 движение черепахой задаётся командой `ros2 topic pub`, а не
  интерактивной клавиатурой — реального человеческого ввода здесь методичка
  не требует, поэтому весь опыт воспроизведён скриптами один в один по
  шагам руководства.
- Техническая находка, зафиксированная как есть: `ros2 launch`, остановленный
  сигналом извне (не через реальный терминал), не завершает дочерний
  `turtlesim_node`, если сигнал отправлен только процессу-лидеру без его
  группы процессов; рабочее решение — открывать `ros2 launch` через `setsid`
  и слать `SIGINT` всей группе (`kill -INT -- -PID`), что и сделано в
  скриптах сбора `evidence/pr02/launch-run.txt` и
  `evidence/pr02/launch-nodes.txt`.
- Проверка: все файлы в `evidence/pr02/` — реальный stdout собранных и
  запущенных команд в том же контейнере; координаты черепахи после
  `ros2 topic pub` воспроизводимы (совпадают при одинаковом стартовом
  состоянии в разных прогонах).

## ПР03

- Затронутые файлы: `src/patrol/` (пакет, нода, юнит-тест),
  `.github/workflows/ci.yml` (сборка и pytest вместо проверки ПР02),
  `evidence/pr03/demo.md`, `evidence/pr03/report.json`, эта декларация.
- Помощь ИИ: генерация каркаса пакета, реализация ноды `patrol` (подписка,
  таймер, чистая функция `select_command`) и её юнит-теста по условию
  методички, написание и запуск скриптов для воспроизведения разрыва/
  исправления через remap и измерения реальной частоты команды, оформление
  `demo.md` по фактическим наблюдениям.
- Полностью автоматизировано: методичка ПР03 не требует интерактивной
  клавиатуры — движение задаётся таймером ноды, разрыв связи
  демонстрируется через `ros2 run` без/с `--ros-args -r`.
- Наблюдение, зафиксированное как есть (не домысел из методички, а
  собственное измерение): после остановки ноды `patrol` черепаха не
  останавливается мгновенно — координаты успевают измениться ещё примерно в
  течение секунды по инерции последней команды, и лишь затем скорость
  оседает в ноль; это подтверждено двумя последовательными чтениями позы с
  интервалом в 2 секунды (см. `evidence/pr03/demo.md`).
- Проверка: `evidence/pr03/build.txt` и `tests.txt` — реальный вывод
  `colcon build` и `pytest` (2/2 пройдено); `demo-run.txt` — реальный вывод
  `ros2 topic info`/`ros2 topic hz`/`ros2 topic echo` из того же контейнера,
  ничего не сгенерировано вместо фактического запуска.

## ПР04

- Модель и инструмент: Claude Sonnet 5.5, приложение Claude Code. Работа
  выполнена на MacBook (Apple Silicon): Docker Desktop, XQuartz, тот же образ
  ROS 2 Lyrical по закреплённому digest под эмуляцией amd64.
- Затронутые файлы: `src/patrol/` (`patrol.py`, три файла тестов,
  `test_mypy.py`, `package.xml`, `setup.py`), `.github/workflows/ci.yml`
  (сборка `patrol`, весь каталог тестов и проверка ПР04 вместо ПР03),
  `evidence/pr04/`, эта декларация.
- Характер помощи: реализация параметров `linear_speed`/`turn_rate`/
  `publish_hz`, чистых функций `validate_param` и `choose_cmd`, пересоздания
  таймера и тестов (чистые функции и живая нода); отдельная ветка
  `defect/pr04-no-hz-check` с отключённой проверкой частоты; скрипты для
  воспроизведения опыта и оформление `parameters.md`, `report.json`.
  Реализация написана с нуля по условию с сайта курса; чужие реализации как
  источник кода не использовались.
- Что сделано человеком: перенос рабочего окружения на новый компьютер и
  подтверждение, что окно turtlesim открывается. Сам опыт ПР04 не требует
  интерактивного ввода (параметры меняются командами `ros2 param set`) и
  выполнен скриптами; команды и их вывод сохранены без правки.
- Находки, зафиксированные как есть: на дефектной ветке `ros2 param set
  /patrol publish_hz 0.0` не получает ответа, а нода падает с
  `ZeroDivisionError`; сгенерированный `test_mypy` из корня репозитория
  падал на одноимённых `setup.py` из `build/` и соседнего пакета, поэтому
  его запуск привязан к каталогу пакета; под эмуляцией CLI `ros2 topic hz`
  стартует несколько секунд, поэтому окно замера увеличено до 20 с.
- Способ проверки: `evidence/pr04/tests.txt` — `python3 -m pytest
  src/patrol/test -v` (44 passed, 1 skipped); `defect-tests.txt` и
  `fixed-tests.txt` — одни и те же 37 тестов на дефектной (13 failed) и
  исправленной (37 passed) версиях; `good-*`, `defect-live-*`,
  `fixed-live-*` — реальный stdout и коды завершения `ros2 param`/`ros2 topic
  hz` на запущенной ноде.
